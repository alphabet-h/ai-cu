# 安全機能 (詳細)

README の「安全機能」の詳細。[README に戻る](../../README.md#安全機能)

文中の `D-xxx` は、[判断の記録](../decisions.md) の番号。

使う前の注意 (本物の入力を動かすこと、無保証、設定ファイルが境界であること) は [README の「注意」](../../README.md#注意) にだけ置く。

- **既定で拒否 (fail-closed)**: 設定が無い、または `input_enabled` / `capture_enabled` が false なら、実入力と撮影を拒否する。`validate` と `--dry-run` は設定が無くても使える
- **設定の allow / deny**: [「設定ファイル」](config.md) の 5 つの次元で宣言する。人間の設定が基本の層で、`--config` や環境変数は deny を足せるが allow を広げられない。プロセス名を読めないウィンドウは、どれかの層に `deny.processes` があれば、入力で断り、`windows` の一覧と名指しでは無いものとして扱う (D-145)
- **事前検証 (`validate`)**: 操作列の形、ポリシー、上限、画面の範囲を、装置に触れずに確かめる。`run` も実行の前に同じ検証を通す
- **`--dry-run`**: 入力を送らず (入力の装置を作らず、読むのは画面の大きさだけ)、検証の結果と、各操作がどの入力のバッチに展開されるかを出す
- **フォアグラウンドガード**: `SendInput` の各バッチの直前に、入力が届く先 (マウスは座標の下のウィンドウ、キーは前面のウィンドウ。修飾キーつき (`modifiers`) の `click` / `double_click` は両方。D-137) を取り直してポリシーに通す。管理者権限のウィンドウ (UIPI で入力が届かず、失敗も検出できない) と、権限を確かめられないウィンドウには送らない。1 つの操作 (`type`) のキーの束は、最初の束の前面のプロセスに固定し、途中で別のプロセスの窓が前面になれば残りを送らずに 7 (`target_changed`) で止める。同じプロセスの別の窓 (ダイアログ) への移りは止めない。UWP のアプリどうし (前面のプロセスが共通の `ApplicationFrameHost.exe`) の移りは見分けられないと推定している (確かめていない。D-100)。応答しないアプリの代わりに OS が出すゴーストのウィンドウ (クラス `Ghost`) には、設定にかかわらず送らない (届く先がゴーストなら、マウスもキーも 7。D-119)。マウスの点がどのモニターの上にも無い (モニターの間の隙間) か、カーソルの動く範囲 (`ClipCursor`) の外なら、OS がカーソルを寄せて判定していない窓に届くので、点の設定と点の下の窓の判定の前に 7 (`off_monitor` / `cursor_clipped`) で断る (範囲を読めなければ送らずに 8、5 なら 14。D-151)
- **起動した側の除外**: ai-cu を起動した側 (親プロセスの連鎖: エージェント、シェル、端末、Claude Desktop など。その子のコンソールも) のウィンドウには、設定にかかわらず送らない (終了コード 7)。`focus` と `close` と `resize` と `window` 指定の撮影と要素の読み取り (`find`、`tree`、`text`、`wait_for`) の名指しでは探さない (下の「名指しの範囲」)。`region` と全画面の撮影には、矩形に入っていれば写る (deny に当たっても数えない。D-077、D-101)。連鎖は起動時に 1 回たどり、PID の再利用を作成時刻の比較で防ぐ。シェル (explorer.exe) の手前で止める (D-055)
- **名指しの範囲** (D-139): 窓を実行ファイル名と題名で名指しする操作 (`focus`、`close`、`resize`、`wait_for`、`screenshot` / `wait_stable` / `wait_change` の `window`、`shot --window`、`find`、`tree`、`text`) は、`windows` の一覧に出る窓 (設定のプロセスとクラスの判定を通り、ai-cu を起動した側でない。操作列ではさらに TUI の端末でない) だけから、前面に近い順に探し、ポップアップらしくない窓の中の最初の一致、無ければポップアップらしい窓の中の最初の一致を選ぶ (ポップアップらしい窓は `WS_EX_NOACTIVATE` か、題名の帯の無いポップアップ。ツールチップなど。外しはせず後に回す。D-143)。許可の外と起動した側の窓は、あっても無いときと同じ結果 (12。`focus` は 11 の `not_found`。message の末尾に「許可の外と ai-cu を起動した側の窓は探さない」旨の 1 文が付き、撮影の 12 の `error.detail.window` も無い) になるので、名指しの成否、終了コード、message から `windows` に出ない窓の有無と題名 (題名は部分一致) を当てられない。同じ実行ファイル名で前面に近い許可の外の窓があっても、後ろの許可された窓が見つかる。実行ファイル名だけの判定は探す前に掛け、許可の外の名前は窓が無くても 4 (名前は窓の有無に依らないので漏れない)。探した後の権限 (管理者) の 7 は残る (管理者の窓は `windows` に出る)。撮影の許可 (`general.capture_enabled` と、`allow.actions` / `deny.actions` の `screenshot`。`windows` の 4 と同じ判定) が無いとき、入力の許可だけで動く `focus`、`close`、`resize` は許可された窓の題名も読ませない: 結果の `focused[].title`、`closed[].title`、`resized[].title` を null にし、失敗の message の対象の表示から題名を外し (`process` と `hwnd` だけ)、`title` での名指しを検証で 4 で断る (部分一致の成否で題名を 1 文字ずつ当てさせないため。`close` は `title` が必須なので常に 4)。`error.rule` と `error.fix` は撮影を断った軸のもので、`hint` は `title` を外して `process` だけで名指しすれば `focus` と `resize` は通ることを伝える。`process` だけの名指しの成否で、その実行ファイルの許可された窓があるかは分かる (入力の許可の範囲で、題名ではない。D-152)。限界: `wait_for` は許可の外と起動した側の窓を無いと数えるので、そうした窓は待てない (`absent: false` は時間切れまで待って 15、`absent: true` は最初の確認で満たされる)。ポップアップらしい窓を後に回すこと (D-143) の限界: 印は経験則で、確かめたのは Windows 11 のメモ帳のツールチップ (PopupHost) だけ。枠の無い本体 (`WS_POPUP` で `WS_CAPTION` がそろわない。ボーダーレスのゲームや、自前で枠を描くアプリの一部) はポップアップらしい側になり、同じプロセスにポップアップらしくない一致の窓があれば後に回る。`windows` の一覧の最初の一致と名指しで解ける窓が違うことがあり、どの窓が後に回ったかは出力から分からない (狙いを確かにするには title で絞る)。本体が許可の外でポップアップだけが許可の内なら、ポップアップに解ける。ポップアップの中身 (メニューやフライアウトの項目) を `find` / `tree` / `text` / `wait_for` の要素で読むときは、process だけだと本体に解けるので title (例 PopupHost) で絞る (本体の UIA の木にポップアップの中身が入るかは確かめていない)。`close` で title がポップアップと本体の両方に当たると、本体に `WM_CLOSE` が届く (title は一意に当たるものにし、結果の `closed` で確かめる)
- **緊急停止**: 各バッチの前、ドラッグの補間の各ステップ、待機の途中 (50 ミリ秒ごと) で確かめる。停止要因は、目印のファイル (`stop.sentinel_file` と環境変数 `AI_CU_STOP_FILE`)、最大実行時間、利用者のマウス操作 (自分が動かした位置から `mouse_threshold_px` を超えて離れたら停止)。送った移動がカーソルの動く範囲 (`ClipCursor`) に寄せられて離れたときは、6 の `reason` を `cursor_clipped` にして人の操作と分ける (範囲を読むのは移動を送った後に離れたときだけ。D-151)。MCP ではクライアントの取り消しと標準入力の EOF も停止要因になる。停止や失敗のときは、押したままのキーとボタンをすべて離す。最大実行時間 (`limits.max_duration_ms`) は操作の前の予告の間を数えず、予告の後から数える (短い上限で予告が上限を食わないように)。予告の間も 50 ミリ秒ごとに目印のファイル、MCP の取り消し、利用者のマウスを見る (D-093)。別の ai-cu の入力の錠の待ちの間も 50 ミリ秒ごとに目印のファイルと MCP の取り消しを見る (マウスは見ない。動かしているのは前の ai-cu なので。D-113)
- **操作の前の枠と予告の間** (D-093): 画面を変える操作 (マウス、キー、文字入力、`focus`、`close`、`resize`、`clipboard`) を含む実行では、検証と操作前の判定 (ロック、押されたままのキー) が通った後、最初の操作の前に、すべてのモニターの縁に青い枠 (約 6 px、内側に向けて薄くなる) と、上の中央に案内の札「ai-cu が操作中 — マウスを動かすと止まる」を出す。枠が出ていなければ `indicator.lead_ms` (既定 3000) 待ってから動く (予告の間。`indicator.sound` なら、待ちに入るときに通知音を 1 回鳴らす)。予告の間に、マウスを動かすと 6、キーかマウスに触れると (始めの 300 ミリ秒は除く) 何も送らずに 10 (`reason: lead_input`) で止まる。予告を省くのは、自分か他の ai-cu の枠が `lead_ms` 以上前から出ているとき (常駐の MCP の連続の呼び出しや、別の AI が操作を終えて残している枠、重い検査の実機テスト (tests/fixture_real.rs) がフィクスチャを開いている間。D-094。`python scripts/verify.py --ignored` が段の始めから終わりまで出す枠はクラス名が別 (`ai_cu_verify_frame`) で、ai-cu の枠に数えないので、それが出ていても予告は省かない。D-111)。他の ai-cu の枠が出たばかりなら、残りだけ待つ。ただし枠を読むのは入力の錠 (下の入力の排他) を取った後で、別の AI が画面を変える操作の最中なら、その実行が終わって錠が解けるのを待ってから枠を読む。錠を待った実行は、枠が出ていても予告を省かず縮めず、`lead_ms` をまるごと待つ (D-113)。複数の AI が同時に動かすと、それぞれが自分の枠を出す (重なって少し濃く見える)。入力が交ざらないようにする排他は、入力の錠で行う (D-113)。実行が終わると、CLI はすぐ、常駐の MCP は最後の呼び出しから 30 秒後に枠を消す (出ている枠は、装置に触れる道具の呼び出しのたびに 30 秒後まで延びる。D-107)。人か停止要因に止められた実行 (6 と、10 の `lead_input`。6 のうち `cursor_clipped` は人の操作ではないので除く。D-151) の後は、すぐ消す (残すと次の実行が予告と人の入力の判定を省いてしまう)。枠を出していない実行 (読み取りの `wait_for`、待ちや撮影だけの `run`) が止められたときも、前の呼び出しが残した自分の枠を消す。常駐の MCP は、実行の後に届いた取り消しでも消す。TUI からの実行は枠を出し、予告の間は省く (カウントダウンがある。TUI は開いている間錠を持つので、TUI の中の実行は錠を待たない。D-147)。撮影だけ、待ちだけ、`find` などの読み取り、`--dry-run`、`validate`、操作前の判定で断る実行、ロック中に始まる close と resize だけの操作列では出さない。枠は撮影から外していて (`WDA_EXCLUDEFROMCAPTURE`)、ai-cu の撮影にも画面録画や画面共有にも写らない。クリックを素通しし、前面を取らず、`windows` の一覧 (隠れた窓の `hidden_windows` を含む。どの ai-cu のプロセスの枠も) と前面のガードと撮影の覆いの判定にも出ない。枠は知らせる手段で、守りの層ではない: 枠を出せなくても (窓を作れない、撮影から外せない) 実行は止めず、予告の間は待ち、標準エラー (MCP では `--log` のファイルにも) に警告を 1 行書く。起動に失敗したら 60 秒たった次の操作で立て直し (時間切れのときは止まった枠のスレッドが片付いてから)、常駐の MCP では `status` の `indicator.frame` で状態と理由を読める (D-103)。主スレッドが固まっても、枠は期限 (予告の間 + 最大実行時間 + 残す時間 + 2 秒。呼び出しで延ばした後は、最後の延長から 30 秒) で自分で消える
- **入力の排他** (D-113): 画面を変える操作 (マウス、キー、文字入力、`focus`、`close`、`resize`、`clipboard`) を含む実行は、検証が通った後、操作前の判定 (ロック、押されたままのキー) と枠・予告の間より前に、セッションごとの名前付きミューテックス `Local\ai-cu-input` (入力の錠) を取り、押したままのキーとボタンを離して枠を解いた後に解く (失敗と停止の後も解く)。別の ai-cu (別の AI か、人が動かしている ai-cu) が画面を変える操作の最中なら、その実行が終わるまで待つので、2 つの AI のクリックや文字が交ざらない。待つ間も 50 ミリ秒ごとに目印のファイルと MCP の取り消しを見て、止まれば何も送らずに 6。30 秒待っても取れなければ、何も送らずに 16 (`input_busy`、`error.detail.waited_ms`)。錠を待った実行は、予告の間を通るなら (枠が有効で、始めのカーソルが読めるとき)、縮めず `lead_ms` をまるごと待つ (前の AI を止めた人の入力を見てから動く)。枠を切った設定 (`indicator.enabled = false`) と、ロック中に始まる close と resize だけの操作列は予告の間を通らないので、待った後も人の入力を見ずに送る (人の入力は各バッチの前のマウスの監視 (6) だけが拾う)。撮影だけ、待ちだけ、`find` などの読み取り、`--dry-run`、`validate`、検証で断る実行は錠を取らず、待たない。実行は錠を 1 回の実行の間だけ持ち (TUI は開いている間ずっと持つ。D-147)、MCP の呼び出しをまたいでは持たない (`focus` → `click` → `type` を交ざらせたくなければ 1 つの `run` にまとめる)。前の持ち主が解かずに終わった (強制終了など) 錠は取れる (残ったキーは続く押されたままのキーの確認が拾う)。錠を作れない・開けない・試せない (権限の違う ai-cu が先に作った錠、同じ名前のミューテックスでない物など) ときは、何も送らずに 8。別のセッション (RDP など) の ai-cu とは排他にしない (入力の届く先が違う)。待った時間は `elapsed_ms` と `limits.max_duration_ms` に数えない。人が TUI を開いている間、別の ai-cu の画面を変える操作は (TUI 以外の窓あてでも) 30 秒待って 16 になり、TUI の編集に届かない。TUI の中の実行は同じスレッドで錠を取り直すので待たない。TUI が錠を待つ間 (別の ai-cu の実行中、別の TUI) は Ctrl+C 以外のキーを受け付けない。錠を開けないとき (権限の違う ai-cu が先に作った錠など) は編集を許し、打鍵を防げないことを警告で出し続ける (そのとき同じ権限の他の ai-cu も錠を開けずに 8 で何も送らない)。ai-cu の錠を見ない道具の打鍵は防げない
- **入力の前の画面とキーの確認**: 操作列に入力、`focus`、撮影 (`wait_stable` と `wait_change` を含む) のどれかがあれば、操作に入る前にセッションのロック (WTS) と入力デスクトップを読み、画面のロック、スクリーンセーバー、UAC などの別の画面なら、何も送らずに終了コード 14 (`desktop_unavailable`) で断る。`shot` も撮る前に同じ確認をする。入力があれば、続けて Shift、Ctrl、Alt、Win とマウスのボタンが押されたままでないかを実行の最初に 1 回だけ見て、押されていれば何も送らずに 10 (`reason: keys_held`) で断る (人の押下が入力に混ざらないように。代わりに離すことはしない)。途中のステップでは、撮影と focus の直前に同じ判定を通し (`wait_stable`、`wait_change`、`screenshot` の `settle` は撮るたびに。待つ間にロックされれば次の撮影で 14)、ロックとセーバーなら 14、判定が読めなければ 8。入力のステップは、入力デスクトップが切り替わった後 (資格情報の画面など) なら 14、ロックの幕の間は前面のガード (7) が断る。撮影を付けない `close`、`resize`、`clipboard`、`wait`、`wait_for` だけの操作列は確認しない (ロック中も閉じられる、大きさを変えられる、クリップボードに置ける、待てる。続く貼り付けの `key` はロックの判定で止まる。D-066、D-067、D-068、D-150、D-157)
- **パスワード欄への入力の拒否**: キーボードのフォーカスがパスワードの要素 (UIA の IsPassword。`GetFocusedElement` で読むシステム全体のフォーカス) にあれば、`type` と `key` を既定で何も送らずに終了コード 4 (`error.rule` が `general.password_input`、`error.detail.window` は前面の窓) で断る。どの層も `general.password_input = true` のときだけ許す。順は「フォアグラウンドガード → フォーカスの要素を読む → (通すなら) 緊急停止の確認とガードをもう一度 → 送る」で、読む間に前面のウィンドウが変わったら、読み直さずに何も送らずに 7 で断る (`error.detail.window` は変わった後の窓)。UIA の待ちは 1000 ミリ秒 (`IUIAutomation2` の接続と処理の時間切れ)。`--dry-run` と `validate` では読まない。読み取りの側では、`text` と `wait_for` の文字列の条件がパスワードの要素の文字列を読まずに飛ばし、`find` の要素に `password` が出る。フォーカスの判定が時間切れ (UIA 自身の時間切れ、または 4 秒で返らない) のとき、または返らない判定が 4 本残っているときは、何も送らずに 8 で断る (D-104。断るときの文は、起きやすい場面と次の手を言う。D-163)。限界: 読めないアプリ (UIA を出さないアプリ、フォーカスの要素が無い、IsPassword が読めない) では通す (fail-open)。判定は各操作の最初のキーの束の前と、Tab か Enter を送った後の次のキーの束の前で行う (`type` の途中の Tab や改行でパスワード欄に移れば、その後は送らない。ただし判定は次の束の直前で、`interval_ms` (既定 20) の間にアプリがフォーカスを移し終えていなければ、移る前の要素を読んで通しうる)。アプリが自分でフォーカスを動かした場合 (Tab や Enter 以外のきっかけ) は、同じ操作の中では見ない。`click` の直後の `type` は、`click` の後の 200 ミリ秒の落ち着き待ちの後のフォーカスで判定するので、フォーカスの反映が遅いアプリでは前の要素を読んで通しうる (D-090)
- **パスワード欄の右クリックとドロップの拒否** (D-149): 同じ許可 (`general.password_input`) で、マウスの 2 つの経路も断る。右クリック (右ボタンの押下を含む `click`、`double_click`、修飾キーつき、右ボタンの `drag`) は押す点の、`drag` は押す前に離す点 (`to`) の、点の下の UIA の要素 (`ElementFromPoint`) の IsPassword を読み、パスワードの要素なら何も押さずに 4 (`error.rule` が `general.password_input`、`error.detail.point` が読んだ点。窓は入れない) で断る。右ボタンの `drag` は押す点を先に、離す点を後に読む。順は「ガード (ドロップは、離す点だけのマウスのガードを送らずに試し、通れば読む) → 読む → (通すなら) 緊急停止の確認と押す束のガードをもう一度 → 押す」。離す点が許可の外なら読まずに飛ばし、今どおり押した後の途中の移動か離す束のガードで 7 になる (D-132。途中まで送ってあり、押したボタンは離してある)。左クリック (修飾キーつきを含む)、`move`、`scroll` では読まず、断らない (送信やフォーカスの移動はクリックで行える)。どの層も許していれば読まない。`--dry-run` と `validate` では読まない。時間切れは何も押さずに 8 (D-104。断るときの文は、起きやすい場面と次の手を言う。D-163)。限界: 押す前の判定なので、ドラッグの間に離す点の下が変わっても見ない。ドラッグの途中で止まった・断られたときの後始末の離し (最後にガードを通った点。D-038) は判定しない。開いたメニューの項目 (「貼り付け」など) やアプリ自身の貼り付けは見ない。読めないアプリ (UIA を出さない、点の下に要素が無い、IsPassword が読めない) では通す (fail-open)
- **組み込みの拒否**: `Win` を含む組み合わせ、`Alt+F4`、`Ctrl+Alt+` 系、`Ctrl+Shift+Esc`、`Ctrl+Esc`、`PrintScreen` (修飾キーにかかわらず。クリップボードを経て撮影の制限の外で画面を得る経路になるため。D-141) は送らない。`click` / `double_click` の `modifiers` に `ctrl` と `alt` を両方書いたクリック (修飾キーつきのクリックの Ctrl+Alt) も同じく断る (4。D-137)
- **撮影の制限**: 全画面の撮影は設定で許したときだけ (既定は拒否)。`shot` は人が操作中 (最後の入力から `capture.min_idle_ms` 未満) なら撮らずに終了コード 10 で断る。点の色を読む `pixel` も、`shot` と同じ許可 (`screenshot` の許可) と守り (ロック、領域の規則、無操作の 10、機密のウィンドウの 7) を点ごとの 1x1 の矩形に掛け、どれか 1 点でも断れば何も読まない (D-146)。画面を読む待ち (`wait_for`、`wait_stable`、`wait_change`) も、自分の名前の許可 (`allow.actions` / `deny.actions`) に加えて撮影の許可 (`general.capture_enabled` と、`allow.actions` / `deny.actions` の `screenshot`) が要り、無ければ検証で終了コード 4 で断る (`error.rule` と `error.fix` は撮影を断った軸のもの。待ちから窓の題名、要素の名前、文字列を読ませないため。D-153)。撮った画像には画面上の個人情報が写りうる
- **機密のウィンドウを撮らない**: どれかの層の `deny.processes` か `deny.classes` に当たるウィンドウが、撮る矩形 (`--region`、全画面、`window`。操作列の `screenshot`、一手ずつの `--shot`、MCP、TUI の実行も) に 1 ピクセルでも見えていれば、撮らずに終了コード 7 で断る (`error.detail` の `window` と `visible`)。`pixel` も同じで、窓の重なりを 1 回だけ読んで点ごとの 1x1 に当て、どれかの点に見えていれば何も読まずに 7 で断る (点の間にあるだけなら断らない。D-146)。`wait_stable`、`wait_change`、`screenshot` の `settle` は撮るたびに判定するので、待つ間に撮る矩形へ deny のウィンドウが現れても、その撮影で 7 で止まる (D-081)。判定は見えている部分で行い、Z 順でそれより前面にある不透明なウィンドウの枠の矩形を引く。リージョンが枠をまるごと覆わないウィンドウ (`SetWindowRgn` で形を変えたもの) は覆いに数えない (D-112)。前面のウィンドウに完全に覆われていれば通る。ai-cu を起動した側と TUI の端末のウィンドウは、deny に当たっても数えない (覆いとしては引く)。deny の部分を塗りつぶして撮ることはしない。撮る矩形は実行時に決まるので、`validate` と `--dry-run` では判定しない。どの層も deny のプロセスとクラスを書いていなければ、この判定のためのウィンドウの列挙もしない。ただし `window` で撮る対象が別のウィンドウに隠れていて 7 で断るときは、`error.detail` (覆っている窓の `visible` と `see_through`) のために、deny の有無によらず失敗のときだけ列挙を 1 回読む (隠れが解けて撮れたときは読まない。D-135)。限界: 判定と撮影の間にウィンドウが動く競合は防がない (数ミリ秒)。`WS_EX_LAYERED` のウィンドウは、`GetLayeredWindowAttributes` で不透明 (色キーが無く、alpha が無いか 255) と読めたときだけ覆いに数えるが、`WS_EX_LAYERED` を持たずに透けるウィンドウ (DirectComposition。Electron の transparent や WinUI) は覆いとして引くので、その後ろが写りうる (`WS_EX_NOREDIRECTIONBITMAP` は不透明なウィンドウ (ブラウザ、エディタ) も持つので見分けに使えない)。形を変えたウィンドウのリージョンの座標が DPI 認識の違うウィンドウでも同じかは確かめておらず、DPI の違うモニターを 2 枚以上つないだ構成では一部だけのリージョンのウィンドウを覆いに数えて後ろが写りうる。リージョンを読めないウィンドウはリージョンが無いとみなす (D-112)。右から左のレイアウトのウィンドウは、リージョンが枠と同じでも覆いに数えない (座標の原点が右上で、測っていない。D-112)。撮影から外れるウィンドウ (`WDA_EXCLUDEFROMCAPTURE`) と、DWM の枠が取れないウィンドウは覆いに数えない。deny のアプリが応答しなくなると OS が元のウィンドウの代わりにゴーストのウィンドウ (クラス `Ghost`、題名は元の題名に「(応答なし)」) を出し、その持ち主は deny に当たらないが、画面に見えているウィンドウ (撮る矩形の外も含む) に応答しない deny のウィンドウ (`IsHungAppWindow`) が 1 つでもあれば、クラス `Ghost` のウィンドウをすべてその deny のウィンドウとして数える (ゴーストと元のウィンドウは結ばないので、ゴーストを動かしても当たる。ゴーストで当たったときは `error.detail.window` はゴースト。ゴーストが元のウィンドウの後ろに立つ並びでは、見えている元の deny のウィンドウで当たる。D-115)。限界: 元のウィンドウが隠れるか cloaked になる版の Windows では、応答しない deny のウィンドウが見えているウィンドウに入らず数えない (この PC の Windows 11 では見えたまま残った)。応答しない deny のウィンドウと deny でないアプリのゴーストが同時にあると、後者でも断る。眠りが明けた直後に応答しない印が先に消えてゴーストが残る隙間は観測されなかったが、20 ms より短い隙間は否定できない (D-115)。Windows 11 の前面のウィンドウの角の丸みの分 (推定で数ピクセル四方) は覆いとみなすので、後ろの deny のウィンドウの角が写りうる (D-077、D-112)
- **保存先の制限**: 撮影の保存先は `.png` に限り、PNG でない既存ファイル (フォルダを含む) は上書きしない。`capture.save_dirs` で保存のフォルダを絞れる。どれも撮る前に終了コード 4 で断り、書く直前にも同じハンドルで確かめ直す (D-075)。限界: `save_dirs` はパスの字面で判定し、許したフォルダの中のジャンクションやシンボリックリンクをたどらない (リンクの先が外でも書ける)
- **失敗したときの撮影** (D-158): 操作列の `on_error` (一手ずつの `--shot-on-error`、MCP の `shot.on_error`) の 1 枚は、`screenshot` の操作と同じ守り (撮影の許可、全画面の禁止、保存先、入力デスクトップ、窓の解決と隠れの待ち、領域、機密のウィンドウ) を通す。検証は操作に入る前に済ませ、当たれば何も送らずに断る。撮るのは操作に入った後の失敗だけで、停止 (6)、人が操作中 (10)、ロック・セーバー (14) では撮らない (止めた人と使っている人の画面、ロック画面を撮らない)。撮るのは押したままのキーとボタンを離した後で、入力の錠と予告の枠は持ったまま (枠は撮影に写らない。D-093)。撮る前に停止の判定 (目印、取り消し、最大実行時間、利用者のマウス) を通し、そこか撮影の途中で人が止めれば撮らず、元の失敗のコードによらず後始末を停止と同じにする (枠をすぐ解き、MCP は実入力を断る待ちを立てる)。撮れなくても元の失敗は変えない
- **MCP のログの行き先と中身**: `ai-cu mcp --log PATH` は拡張子 `.log` (大文字小文字は問わない) のファイルにだけ追記する。`\\?\`・`\\.\`・`\??\` で始まるパスと `:` を含むファイル名 (代替データストリーム) も断り、断ったら標準エラーに 1 行書いてログなしで続ける (MCP は止めない)。記録の改行と制御文字は `\u{a}` の形に置き換え、本文は 4096 バイトで切るので、クライアントの名前などの相手の決める文字が行を割らない。設定ファイルの TOML の誤りの文は、行と列と誤りの説明だけで組み、元の行を載せない (D-140)。限界: UNC (`\\host\share\x.log`) は通す。拡張子 `.log` の名前のハードリンクやシンボリックリンクの先は追わない。トップレベルに `version = 1` を持つ TOML では、最初の未知のキーの名前 (と、知っているキーで型が違えばその値) が誤りの文に載る
- **設定ファイルの守り**: 設定ファイルが人と AI の境界なので、AI に書き換えさせない。Claude Code では設定ファイルの `Edit` を deny にする (`ai-cu guide --setup` が例を出す)。ただし `Edit` の deny は、シェル (Bash、PowerShell) からの書き換えを止めない。AI にシェルを許すなら、設定ファイルを AI の届かない所に置く (別の利用者の持ち物にする、AI を動かす利用者の書き込みを ACL で外す) か、AI のシェルの書き込みを Claude Code の権限で絞る
- **毎回の承認 (MCP)**: 設定の `mcp.require_approval` に書いた道具は、`tools/list` で `anthropic/requiresUserInteraction` の印が付き、Claude Code はモードや allow のルールにかかわらず呼ぶたびに人の確認を出す (dontAsk のモードでは拒否)。設定が読めない間は `guide` を除くすべての道具に印を付ける。限界: 印は客への依頼で、ai-cu は `tools/call` で人が確かめたかを知れず見ない。印に対応しない客 (Codex など) は無視する。印は道具の名前ごとなので、`click` だけ書いても同じクリックを `run` で呼べば印は付かず、`shot` も一手ずつの道具の撮影や `wait_stable` には及ばない (入力の道具を書くなら `run` も書く)。`key` を書いても、`click` / `double_click` の `modifiers` で押す修飾キーには印が付かない (確認を求めるなら `click`・`double_click`・`run` も書く。止めるなら `deny.actions` の `key`。D-137)。設定の変更は客が一覧を取り直したとき (`/mcp` の再接続) に効く (D-078、D-101)
- **前面化の制限**: `focus` は、設定で許されたウィンドウに `SetForegroundWindow` を 1 回呼ぶだけ。復元 (`SW_RESTORE`) と前面ロックの回避策 (Alt の空打ち、`AttachThreadInput`、`AllowSetForegroundWindow`、`SystemParametersInfo`) は使わない。前面が別のアプリなら (人が使っている、または前面のまま置かれている) OS が断り、何も送らずに終了コード 11 で止まる (タスクバーのボタンは点滅しうる)。CLI として呼ぶたびに起動されるときは、ai-cu を呼んだ端末が前面なら OS は断らないので、人が操作中 (`capture.min_idle_ms` 未満) なら前面にせずに 10 で止まる (D-050)。常駐の `ai-cu mcp` は、起動の後の人の入力で前面化の権利を失う。そこで MCP の `focus` だけは、自分の呼び出しが断られ (0)、前面が ai-cu を起動した側 (端末など) のときに限って、自分の実行ファイルを隠しのサブコマンドで窓を作らずに (`CREATE_NO_WINDOW`) 起動し、その使い捨ての子に同じ hwnd への `SetForegroundWindow` を 1 回だけ呼ばせる (子でも基本の層 (と `AI_CU_CONFIG`) を読み、`focus` と同じ判定 (停止の目印、総スイッチと actions、ロック・セーバー、対象の窓、起動した側、deny / allow、管理者権限、無操作の確認) を前面化の前に掛け、通らなければ前面にしない。3 秒で終わらなければ kill する。限界: 子を直接起動したときは枠と予告の間を出さない。判定から前面化までの間の変化 (競合) は防がない。D-138)。前面が別のアプリなら起動しない (補助も断られるので、前面ロックの抜け道にはならない)。それでも断られたら `reason: refused_host_front` の 11 で、回避策は使わず、人に前面に出してもらう (D-056、D-057)。CLI と TUI の `focus` は補助を使わない
- **閉じる操作の制限**: `close` は、設定で許されたウィンドウに、題名を必須にして `WM_CLOSE` を 1 回置くだけ (`Alt+F4` は組み込みの拒否のまま)。強制終了 (`TerminateProcess`) はしない。前面で人が使っているウィンドウは閉じない (10)。閉じるのはデータを失いうるので、実入力と同じく緊急停止、人が止めた直後の待ち、開発シェルの拒否を通す (D-062)。題名が必須なので、撮影の許可が無ければ `close` は常に 4 (題名を見ずに閉じる手は足さない。上の「名指しの範囲」。D-152)。ロック中で、カーソルが読めない close だけの操作列は、利用者のマウスの監視なしで走る (目印のファイルと最大実行時間は効く。撮影を付けた close はロック中は 14。D-066)
- **大きさの変更の制限** (D-150): `resize` は、`close` と同じ守り (設定の allow / deny と `allow.actions`、名指しの範囲、起動した側と管理者権限の窓の拒否、無効な窓の 7 (`target_disabled`)、前面で人が使っている窓の 10、入力の錠と枠、緊急停止、人が止めた直後の待ち、開発シェルの拒否、フィクスチャ専用の装置ではフィクスチャの窓だけ) を通し、`SetWindowPos` に大きさだけを渡す。左上、前面、Z 順は変えず、入力も送らない。相手のスレッドには要求を置くだけ (`SWP_ASYNCWINDOWPOS`) なので、応答しないアプリで ai-cu は止まらない。ただし応答しない窓 (`IsHungAppWindow`) には送らない (置いた要求が列に残り、ai-cu が戻った後に効いて送り直しと重なるため。7 の `not_responding`)。送る直前に読み直した最小化も断る (探した時点と 2 重の確認)。最小化・最大化の窓は元に戻さず 7 (`minimized` / `maximized`) で断る (復元は前面ロックの境界をすり抜けるので使わない。D-050)。ロック中で、カーソルが読めない resize だけの操作列は、close と同じく利用者のマウスの監視なしで走る (目印のファイルと最大実行時間は効く。撮影を付けた resize はロック中は 14)。画面領域の規則は掛けない (変えた窓が deny の窓を覆っても、撮影の判定は覆いを窓ごとに見るので漏れない)。DPI 非対応の窓でも、中身の読み (`GetClientRect` を `MapWindowPoints` で画面に写したもの) は物理で返った (この PC の倍率 1.25 の画面で、DPI 非対応のフィクスチャを測った。docs/design-notes.md)。限界: 送った要求が届く前に相手が応答しなくなると (応答しない窓の判定は約 5 秒の閾値なので、それより短い停止)、ai-cu は上限 (1 秒) で `exact: false` を返し、要求は相手が戻った後に効く。アプリが送った後に自分で大きさを変え直すと、読み直しの上限 (1 秒) の後の大きさは見ない。縁を自前で描くアプリでは、`client` と `frame` はほぼ同じになる
- **クリップボードの上書き** (D-157): `clipboard` は、`resize` と同じ許可 (`general.input_enabled`、`allow.actions` / `deny.actions`) と、入力の排他、枠と予告の間を通す。人が操作中 (`capture.min_idle_ms`) なら、前面がどのアプリでも置かずに 10 (クリップボードは窓ごとでなく 1 つなので、人のコピーと貼り付けの途中に割り込まない)。置く文には `type` と同じ文字数の上限 (`limits.max_text_len`) とキーの規則 (改行は `enter`、タブは `tab`) を掛け、貼り付けで `type` の守りを回れないようにする。Win+V の履歴とクラウドの同期から外す印を 3 つ付け、印の登録と置き場の確保はクリップボードを開く前に済ませる (そこで失敗すれば中身は変わらない)。置いた文は結果にも `--dry-run` の計画にも出さない。続く `key` の `ctrl+v` は前面のガードとパスワード欄の判定 (D-090) を通る。限界: 元の中身は失われ、戻らない (文字以外の形式も)。印は Windows の履歴と同期の機能に向けたもので、他のクリップボードの監視アプリが守るとは限らない。置いた文は他のどのアプリからも読めるので、秘密を置かない
- **実行時ガード (開発用)**: 環境変数 `AI_CU_DEV_FORBID_REAL_INPUT` が (値を問わず) あると、`SendInput` を呼ぶ最下層、撮影の最下層、`focus` と `close` と `resize` の最下層、クリップボードの書き込み (`clipboard`) の最下層が拒否する (終了コード 9)。その環境では既定の設定の場所も読まない。このリポジトリの開発シェルでは設定していない (検証済みの release ビルドで手動確認を AI が行う運用。D-051)。debug ビルドの `mcp` は、環境変数に関係なく実入力の道具を 9 で断る (MCP のクライアントからの起動は hook に見えないため。D-055)
- **DPI の確認**: Per-Monitor V2 の DPI 認識を宣言できなければ、座標を扱う `run`、`shot`、`pixel` を拒否する (終了コード 8)
- **後始末**: 停止、失敗、`SendInput` が途中までしか挿入しなかった場合も、押したかもしれないキーとボタンを離す。ボタンを押したまま止まったときは、最後にガードを通った点へ戻してから離す。限界: 後始末は離すだけで、修飾キーつきのクリックの送信が OS の誤りで途中まで入ったときは、抑えのキー (0xE8) を送らずに修飾キーを離すので、前面の窓がメニューや入力言語の切り替えに入りうる (D-137)
- **TUI からの実行**: CLI の `run` と同じ経路 (基本の層、検証、フォアグラウンドガード、緊急停止、後始末、開発シェルの拒否、DPI の確認) を通る。判定は保存済みの設定ファイルで行い、編集中の値は使わない。ai-cu 自身の端末のウィンドウが届く先なら、設定にかかわらず送らない (終了コード 7)。その端末のウィンドウを特定できなければ実行しない。実行後は端末に届いた打鍵を読み捨て、結果の画面では Enter と Esc 以外のキー (Ctrl+C を含む) を無視する。端末の無い起動では TUI 自体が起動しないので、AI の経路は広がらない
- **原子的な送信**: 修飾キーを含む組み合わせとクリック、修飾キーつきのクリック (修飾キーの押下、クリック、抑えのキー 0xE8 の押して離す、修飾キーの逆順の離しを 1 つの束。D-137) は、1 回の `SendInput` で送る
