# 終了コード (詳細)

README の「終了コード」の詳細。[README に戻る](../../README.md#終了コード)

文中の `D-xxx` は、[判断の記録](../decisions.md) の番号。

コードと名前の並びの正は [README の表](../../README.md#終了コード) (`cargo test` が `ErrorKind` と突き合わせる)。`ErrorKind` を変えたら、このファイルの名前の節も直す (テストはこのファイルを見ない)。

## コードごとの意味

### `internal`

内部エラー

### `usage`

使い方の誤り (引数、端末なしでの引数なし起動)

### `invalid_script`

操作列の誤り (JSON、未知のフィールド、形、画面の外の座標)

`resize` の `logical: true` で、窓の画面の DPI で物理に換算した大きさが 16384 を超えたときも 3 で、何も送っていない。倍率は窓を見つけた後に分かるので、実行時に出る (`validate` と `--dry-run` では見えない)。論理の値を下げるか、物理で指定する (D-150)

`clipboard` の文が空のとき、65536 文字 (`char` の数) を超えるとき、改行 (LF・CR) とタブ以外の制御文字を含むときも 3 で、何も置いていない (D-157)

### `policy_denied`

設定による拒否 (総スイッチ、allow / deny、組み込みの拒否、上限、撮影の保存先の規則、パスワード欄への入力。保存先の形と既存ファイルの規則は設定では緩められないので path を直す)。窓の名指し (`find`、`tree`、`text`、`shot --window`、操作列の検証) で実行ファイル名が許可の外なら、窓が無くても 4 (名前だけの判定で、窓を探す前に断る。D-139)。パスワード欄の上の右クリックとパスワード欄へのドロップの 4 (`rule` が `general.password_input`) は、何も押していない。`detail.point` が読んだ点 (右クリックは押す点、ドロップは `drag` の `to`) で、`detail.window` は無い (D-149)。撮影の許可が無いときの `focus` / `resize` の `title` の指定と `close` も 4 (`rule` は撮影を断った軸。`general.capture_enabled`、`allow.actions`、`deny.actions` のどれか。D-152)。画面を読む待ち (`wait_for` / `wait_stable` / `wait_change`) も、撮影の許可が無ければ検証で 4 (自分の名前の許可に加えて撮影の許可が要る。`rule` は撮影を断った軸。D-153)。`clipboard` の文にも `type` と同じ `limits.max_text_len` と、改行を含めば `enter`、タブを含めば `tab` のキーの規則が掛かり、断れば 4 で何も置いていない (D-157)

### `config`

設定ファイルの誤り (構文、未知のキー、未知の版、指定したファイルが無い)

### `stopped`

緊急停止 (目印のファイル、最大実行時間、利用者のマウス操作)。操作の前の予告の間 (D-093) に目印のファイル、マウスで止まったときも 6 で、何も送っていない (`executed` が無い。MCP の取り消しは応答を返さない)。別の ai-cu の入力の錠を待つ間 (D-113) に目印のファイルか MCP の取り消しで止まったときも、錠の待ちの 6 で何も送っていない

送ったマウスの移動が、別のアプリ (ゲーム、リモートデスクトップなど) が絞ったカーソルの動く範囲 (`ClipCursor`) に寄せられ、予定の位置から `mouse_threshold_px` を超えて離れたときも 6 で、`reason` が `cursor_clipped` (人の操作ではない)。`error.detail` は利用者のマウスでの停止と同じ 4 つに、範囲の `clip` (`x`、`y`、`w`、`h`) を足す。それより前の束は送ってある。人を待つ理由が無いので、MCP の止められた後の待ち (10) を立てず、枠も止められた扱いで消さない。範囲を読めないとき、予定の位置が範囲の中のとき、読んだカーソルが予定の位置を範囲の中へ丸めた点 (OS が寄せる先) から `mouse_threshold_px` を超えて離れているとき (範囲が掛かったのと同じ頃に人が動かした) は、今どおり `reason` の無い 6 (D-151)

### `foreground_guard`

フォアグラウンドガード (届く先のウィンドウが不許可、管理者権限、ウィンドウが無い、ai-cu を起動した側のウィンドウ。`focus`、`close`、`resize` の対象の権限 (管理者) での拒否 (許可の外と起動した側の窓は名指しで探さないので 7 にならず、見つからない扱い。D-139)、`window` で撮る対象が別のウィンドウに隠れているとき、撮る矩形に deny のウィンドウが見えているとき (`pixel` では点のどれかの 1x1 に見えているとき。何も読んでいないので、`detail.visible` にかからない点を選ぶ。D-146)、パスワード欄かを確かめる間に前面のウィンドウが変わったときも同じ。修飾キーつき (`modifiers`) の `click` / `double_click` で、前面の窓が許可されていないときも同じで、`detail.window` は前面の窓で、`point` は無い。D-137)。`reason` が `target_changed` なら、1 つの操作 (`type`) の途中で前面が別のプロセスの窓に変わったので残りを送らずに止めた。それより前の文字は送ってある (`partial` が真。`detail` に変わった後の `window` と最初の `pinned_pid`。D-100)。drag の途中で断られたときも途中まで送ってあり (`partial` が真、`detail.point` が断った点)、押したボタンは離してある (D-132)

マウスの点がどのモニターの上にも無い (仮想画面の外接矩形の中の、モニターの間の隙間) なら `reason` が `off_monitor` の 7、カーソルの動く範囲 (`ClipCursor`) の外なら `cursor_clipped` の 7 で、断った束は送っていない (OS がカーソルを近いモニターか範囲の中へ寄せ、判定していない窓にボタンが届くため。drag の途中なら途中まで送ってあり、押したボタンは離してある)。`error.detail` は `point` と `window: null` で、`cursor_clipped` には範囲の `clip` (`x`、`y`、`w`、`h`) も付く。判定は送る時のガードで行い、`validate` と `--dry-run` では見ない。範囲 (`GetClipCursor`) を読めなければ、送らずに 8 (5 なら 14 の `other_desktop`) (D-151)

`close` と `resize` の対象が無効 (モーダルのダイアログを開いている) なら、`reason` が `target_disabled` の 7 で、何もしていない。`resize` の対象が最小化か最大化なら、`reason` が `minimized` / `maximized` の 7 で、大きさの要求を置いていない。ai-cu は窓を元に戻さないので、人間に元に戻してもらってからやり直す (`minimized` は `focus` の 11 の reason と同じ値。D-150)。`resize` の対象が応答していない (`IsHungAppWindow`) なら、`reason` が `not_responding` の 7 で、大きさの要求を置いていない (置いた要求は列に残って後から効き、送り直しと重なるため)。数秒待って `windows` と撮影で確かめてから 1 回だけやり直し、だめなら人間に確かめる (D-150)。この 4 つの 7 には `error.detail` が無い

`window` で撮る対象が別のウィンドウに隠れていて断った 7 (撮影の隠れ) の `error.detail` は、覆っている窓の `window`、隠れを見つけた点の `point`、その窓の見えている部分の外接矩形の `visible`、`see_through` (その窓が deny の窓の判定 (D-077) で覆いに数えない窓か。透けうる窓などで、条件は [「安全機能」](safety.md) の機密のウィンドウを撮らない項。真なら 7。同じアプリの付属の窓を数えない例外 (D-142) も、透ける窓には効かない)。`visible` と `see_through` は読めなければ省く (省く条件は [「使い方」](cli.md) の `error.detail` の一覧)。対象と同じアプリが対象の窓と同じスレッドで出した、題名が無いかツールウィンドウの窓 (ツールチップ、メニューなど) は、透けなければ隠れに数えない (設定で拒否された窓は機密の判定で断る。D-142)。ai-cu を起動した側の窓は撮る対象として探さないので、名指しすると見つからない 12 で `error.detail` は無い (D-139。以前は 7)。`focus` が通っても同じ 7 が続くなら、`focus` を繰り返さず `find` と `text` で読み、画像が要るならその窓 (`error.detail.window`) を片付けてもらうよう人間に頼む。`region` で撮り直さない (`region` には隠れの確認が無く、写り込みの守りの迂回になる。D-135)

### `os_error`

OS の呼び出しの失敗 (`SendInput`、撮影、保存)。UIA の読み取り (find、text、tree、wait_for の要素) が 30 秒で返らなければ 8。返らない読み取りが 4 本残っている間は読まずにすぐ 8 で、ai-cu を起動し直すまで続きうる (D-104)。読みの途中で UIA が時間切れを返したら (対象のアプリが固まったとき)、残りを読まずに 8 (既定の待ちでは UIA の処理の時間切れ 20 秒の 1 回分。20 秒は Microsoft Learn の既定値からの推定で、測っていない。D-110)。時間切れで読めなかった要素を `skipped` に数えたり、属性を空にして入れたりはしない。入力の錠 (D-113) を作れない・開けない・試せないときも 8 で、何も送っていない (`executed` が無い)。message が権限の違うプロセスの錠か、同じ名前のミューテックスでない物を言うときは、やり直しても直らないので人間に伝える

`resize` では、`logical: true` で窓の画面の DPI を読めないとき、窓の大きさの読みが物理と見なせない (中身か枠が外側より大きい) とき、読みそのものに失敗したときも 8 で、大きさの要求を置いていない。窓を見つけた後に分かるので、`validate` と `--dry-run` では見えない (D-150)

`clipboard` では、別のアプリがクリップボードを開いていて、50 ミリ秒おきに 1 秒試し直しても開けなければ 8 (`reason` が `clipboard_busy`。message の末尾に最後の `GetLastError` が付く) で、中身は変わらない。少し待って `clipboard` の手だけを 1 回置き直す。印の登録や置き場の確保に失敗したときも、開く前なので中身は変わらない 8。中身を空にした後に置けなかったときは 8 で `partial` が true になり、クリップボードは空 (元の中身は失われている。D-157)

### `forbidden_dev_env`

開発シェル (`AI_CU_DEV_FORBID_REAL_INPUT`) での実入力と実画面の撮影の拒否

### `user_active`

人が操作中 (最後の入力から `capture.min_idle_ms` 未満) なので、`shot` を撮らなかった、`pixel` で色を読まなかった (D-146)、`focus` で前面にしなかった、または前面にある対象を `close` で閉じなかった、`resize` で大きさを変えなかった (対象かその所有するダイアログが前面のときだけ判定する。D-150)。`reason` が `keys_held` なら、キーかマウスのボタンが押されたままなので、操作列の入力を何も送らなかった (押されたままのキーを人に確かめる。D-066)。`reason` が `lead_input` なら、操作の前の予告の間 (画面の縁に枠を出してから動かすまで) に人がマウスかキーボードに触れたので、何も送らずに止めた (`detail` に `idle_ms` と `lead_ms`。人が離れるのを待って 1 回だけやり直す。MCP では `status` の `retry_after_ms`。D-093)

`clipboard` は前面によらず判定し、人が操作中ならクリップボードに置かずに 10 で止まる。ai-cu 自身の入力の直後も操作中に数えるので、置く順は `[clipboard, click 欄, key ctrl+v]` にする (入力の後に置くなら 3 秒以上の `wait` を挟むか、呼び出しを分ける。D-157)

### `focus_failed`

`focus` の対象を前面にできなかった (見つからない、最小化、閉じられた、Windows が断った。`error.reason` で分かる)。断られたときは前面のプロセスで分ける: 前面 (キーの届く窓) が別のアプリ (`refused_other_app`。人が使っている、または前面のまま置かれている。対象の窓が一番手前に見えていても前面とは限らない。人に頼むときは対象の窓を 1 回クリックしてもらう)、前面は ai-cu を起動した側なのに断られた (`refused_host_front`。常駐の `ai-cu mcp` では、補助プロセスを試しても前面にならなかったときなど。試したかは `error.detail` の `helper`)、前面を確かめられない (`refused_unknown`)。`refused_other_app` で前面が端末のアプリ (`WindowsTerminal.exe` など) なら、コンソールのアプリのために既定のターミナルが開いた対象自身のコンソールの窓のことがある (起動し直すなら新しいコンソールを作らせない。PowerShell なら `Start-Process -NoNewWindow`。message と MCP の hint も言う。D-159)。入力は送っていない (タスクバーのボタンは点滅しうる)

### `window_not_found`

対象のウィンドウ (`screenshot` の `window`、`shot --window`、`find`、`tree`、`text`、`wait_stable` と `wait_change` の `window`) が見つからない、最小化されている、または画面の外。撮影も読み取りもしていない (操作の後の `--shot` や操作列の `screenshot` なら、どこまで済んだかは最上位の `executed` で分かる)。`close` の対象が見つからない、または `WM_CLOSE` を置けなかったときも 12 で、何も閉じていない。`resize` の対象が見つからない、窓の大きさを読む前に消えた、または大きさの要求を置けなかったときも 12 で、大きさは変えていない。ただし `partial` が true の 12 は、大きさの要求を置いた後の読み直しで窓が消えたもので、打ち直さず `windows` で確かめる (D-150)

名指しは `windows` に出る窓 (設定のプロセスとクラスの判定を通り、ai-cu を起動した側でない。操作列ではさらに TUI の端末でない) だけから探す。許可の外と起動した側の窓は、あっても見つからないときと同じ 12 で、message も同じ (末尾に「許可の外と ai-cu を起動した側の窓は探さない (windows に出る窓だけを名指しできる)」が付く)。`focus` の 11 の `not_found` も同じ (D-139)。`windows` に出ていない窓を名指ししていないかを確かめ、出ていなければ人間に許可を頼む

`error.detail.window` (7 と同じ形) は、撮影の対象 (`screenshot`、`shot --window`、`wait_stable` と `wait_change` の `window`) のときだけ入る。最小化は許可された窓のときだけで、画面の外はいつも入り、見つからないときは無い (D-135)

### `element_not_found`

`text` の条件で、文字列を持つ要素が無い (パスワードの要素は読まずに飛ばし、飛ばしたときは message の末尾に「(パスワードの要素 N 個は読まない)」が付く。D-090)。一致したが値を持たない要素があれば、その数を「(一致した要素 N 個は文字列 (値) を持たない。名前は find で読む)」と添える (D-154)。何もしていない

### `desktop_unavailable`

画面がロックされているか、スクリーンセーバー、UAC などの別の画面が前面にある (`error.reason` は `screensaver`、`other_desktop`、`locked` (セッションのロック) のどれか)。待っても再試行しても直らないので、人間に解除を頼む。`executed` が無ければ何も送っていない (D-066、D-067)

### `wait_timeout`

`wait_for`、`wait_stable`、`wait_change` の条件が時間内に満たされなかった。何も送っていない (操作列なら、それより前の操作は済んでいて `executed` で分かる)。`error.detail` に `timeout_ms`、`checks` (確かめた回数)、`unmet` (`wait_for` は `window` / `element` / `text`。`text` は要素はあるが文字列の条件がそろわない (一致した要素が値を持たないときも。そのときは message の末尾に値を持たない要素の数と、名前の変化は `element.name` で待つことが付く。D-154)、`wait_stable` は `stable`、`wait_change` は `change`)、`window` (最後の判定で見た対象。題名なし。無ければ null)。画面の待ちでは、最後に撮った矩形の `rect` と最後の比較の差の `last_changed_ratio` も入る。同じ条件で繰り返し待たない。`wait_for` なら `windows`、`find`、`text`、`shot` で状態と条件を見直す (D-068)。`wait_for` は許可の外と起動した側の窓を無いと数えるので、そうした窓を待つと時間切れの 15 になる (`unmet` が `window` の 15 は、message の末尾に 12 と同じ名指しの範囲の 1 文が付く。D-139)。画面の待ちなら `shot` で今の画面を見て、動き続ける部分 (動画、スピナー、点滅) があれば `region` を狭めるか `threshold` を上げ、変わるのを待っていたなら待つ前に既に変わっていなかったか (待ち始めの画像が基準になる) を確かめる (D-081)

### `input_busy`

別の ai-cu (別の AI か、人が動かしている ai-cu) が画面を変える操作の最中か、人が設定の画面 (TUI) を開いていて (TUI は開いている間ずっと入力の錠を持つ。D-147)、30 秒待っても終わらなかった。何も送っていない。`error.detail.waited_ms` に待った長さ。数十秒待って 1 回だけやり直し、続けて断られるなら人間に別の AI の動きと、設定の画面を開いたままにしていないかを確かめてもらう (D-113)

## 設定による拒否の rule と fix

4 と、許可の外れで断る 7 (入力の届く先。`focus`、`close`、`resize` の対象は許可の外なら名指しで探さないので 7 にならない。D-139) には、当たった設定のキーの `error.rule` と人間向けの直し方の `error.fix` が付く ([「使い方」](cli.md) の出力の形。D-079)。撮る矩形に deny のウィンドウが見えている 7 と、プロセス名を読めない窓の `deny.processes` (D-145。床なしの文も出さない) は `rule` だけで、`fix` は付かない。
